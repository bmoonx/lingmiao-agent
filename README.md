# 灵妙-Agent

> 有问题想直接聊？微信 **`lingmiao-agent`**（备注「lingmiao」）· 也欢迎提 issue

**无状态，是今天所有大模型的底色** —— 它不记得你上一句说过的约束，分不清自己这次推理的对错，也不会承认「这个我做不到」。

**你写下的每一条规范、定过的每一个决策、踩过的每一个坑，它下一轮都可能忘。**

而这些毛病有个共同根子：它不会在对话中更新权重，输出完全由这一轮喂进去的上下文决定 ——

- **不记** —— 跨轮次的连续性无从谈起，关键约束会被越滚越长的历史淹没。
- **不辨** —— 没有证实 / 证伪的反馈，不知道自己是对是错。
- **不自知** —— 它不会告诉你「这超出了我的能力」。

指望模型「自觉」，本质上是在许愿。能兜住这一切的，只有模型外面那一层 —— **Harness**：

- 不是把提示词写得更漂亮，而是把这件「补上下文」的事，**从提示词里的自觉，变成引擎里的架构**。
- 这也是一个来自 Claude Code 深度使用者的判断：**模型不是瓶颈，Harness 才是。**

**灵妙-Agent** 就是围绕这句话做的一次重构 —— 一个用纯 Rust 写成的 Claude Code 风格终端引擎。

它要解决的，正是上面那些毛病：**约束会丢、对错难辨、上下文会爆。**

---

## 为什么是 Harness，而不是把提示词写得更漂亮

当前所有商用大模型都是**无状态**的 —— 不会在对话中更新权重，输出完全由「这一轮喂进去的上下文」决定；同一段上下文，换谁来问，结果都差不多。

这带来三个绕不过去的毛病：

- **不记** —— 跨轮次的连续性无从谈起，关键约束会被越滚越长的历史淹没。
- **不辨** —— 没有证实 / 证伪的反馈，它无法自主判断对错；幻觉、乱决策、工具调用走形，根子都在这里。
- **不自知** —— 它不会告诉你「这超出了我的能力」，任务再离谱也先接着做。

**所以优化模型表现的路只有一条：在对的时候，把它该知道的信息补进上下文。**

RAG 是这个道理；「自然语言编程」被过度宣传，也正卡在这里 ——
模型能处理的，只是自然语言里形式化、逻辑清晰的那部分，直觉、抽象、灵活判断它并不具备。

不少自称「自主行动」的 Agent，本质也只是把固定流程写进了系统提示词 —— 并没有跳出上下文推理的范畴。

再往深一层看，真正稀缺的从来不是模型的能力，而是**人愿意付出的认知负担** ——
判断「哪条信息重要、该放进哪、用什么口径」，向来最耗人。

**所谓 AI 时代的生产力，正是 Harness 把这部分认知劳动接了过去**：
人最低只做一个动作（比如按下录音），提炼、判断、落位交给引擎。

而它不会自己发现哪段材料值得留、哪条该进哪条该弃 ——
**这些「判断」，眼下仍要人指路，或由 Harness 兜住。**

Claude Code 已经把「终端里的编程助手」做到很高水准。但有两道坎，同类几乎都绕不过：

- **AI 不遵循规范。** 作者在提示词工程上下了很大功夫 ——「不要直接改这个文件」「先读再改」「只做这一步」……
  写得再清楚，上下文一长，模型该忘的还是忘。
- **上下文会爆。** 会话越长，关键约束被淹得越深，越跑越歪。

说到底，前人大多把「一个 agent」当成一串**直来直去的 LLM 调用** —— 把越堆越长的对话原样丢给模型，指望它自己在噪声里抓住重点。

而噪声是有来源的：**模型靠注意力机制在上下文里分配权重**，
如今不少模型还上了**稀疏注意力** —— 为了扛住长上下文，只在众多片段里挑一部分重点看。

**喂进去的内容越杂，真正要紧的那几条（约束、决策、上下文）就越容易被稀释。**

灵妙的答案不是把提示词写得更漂亮，而是**重构 Harness 的底层架构 —— 在一次次模型调用的外面，加一层封装**：

- **规范由引擎兜底，不靠模型自觉** —— 提示词里的「请你……」，到引擎里变成「你只能……」。模型记不住，引擎不会忘。
- **每一轮结束，清空上下文** —— 不让历史无限膨胀，连续性交给记忆系统按需召回。
- **每一轮开头，先跑一次「组织上下文」** —— 一次专门的 LLM 调用，只负责从记忆里挑出「这一轮真正该给模型什么」。

这一来一去，模型每轮拿到的 input 都是**干净的**：不是一整段越滚越脏的历史，而是刚刚挑选过、这一轮真正需要的那部分。

**约束不再被淹没，模型自然更听话。**

也正因如此，它**对模型不太挑剔** —— 听话靠的是引擎的边界，不是某个模型格外聪明。

换个便宜模型，规矩照样立得住。

**一次会话里的多次 LLM 调用，从概念上合起来就是一个 agent：**
上下文由引擎组织、约束由引擎兜底、记忆由引擎召回 —— **从 Harness 层面，把模型的开发程度和利用率大幅拉高。**

**而这套 Harness 之上，「自动模式」已经落地。**

单模型再强也是无状态的；而**多个无状态模型经 Harness 协同，能涌现出接近人的决策能力** ——
这是业界的共识，也已有论文与实验验证。灵妙把它做进了 TUI：

- **一条命令拉起双 agent 闭环。** 敲 `/auto <目标>`：一个 agent（Main）执行落地，
  另一个 agent（Auditor）独立掌管验收与打回，不通过就把反馈回注、循环纠错直到达标。
  纠错的内容又成为执行方下一轮的上下文 —— **相当于让模型自己给自己补上下文。**
- **两个 agent 是真正隔离的。** 各自有**自己的工具白名单、自己的记忆区**；
  Auditor 只有「只读 + 检索」的一只手，**物理上改不了代码**，只能看、只能判。
- **跑在隔离的 git 工作树里。** 每轮 checkpoint，主工作树不被污染；
  想只做一次「产出 → 审计」也能敲 `/round <目标>`。
- **过程可见、随时可停。** 左下角与活动行常驻当前轮次与角色（`Auto·Main` · 第 N 轮），`Esc` 立即停下。

而这条路的地基，仍是先把单 agent 做稳：**单 agent 越强，多智能体越容易出效果。**

（安装、配置与用法见[安装部署](#安装部署) / [使用方法](#使用方法)；国内直连见[快速开始](#快速开始)。）

## 代码是怎么把 AI 约束住的

用 AI 编程的人都有同一种累：**提示词写了半天，模型该守的规矩还是没守住。**

根子在于 —— **光靠提示词约束模型，是把执行的希望寄托在模型的记性上。**

灵妙的做法，是把这类约束**从提示词里挪到引擎里**：

| 你想让 AI 守的规矩 | 只写在提示词里 | 灵妙：引擎兜底 |
|---|---|---|
| 「这个阶段只准检索，不准改代码」 | 写一条 IMPORTANT，指望它记住 | 每个阶段只把**该阶段能用的工具**交给模型 —— 组织上下文阶段**根本看不到**改文件的工具 |
| 「关键约束要一直记得」 | 写在系统提示里，随后被上下文淹掉 | 关键约束**每轮重新贴回模型眼前**，不被长对话冲掉 |
| 「先读文件再改」 | 提示词里写规则，它可能跳过 | **没读过的文件，改不动** —— 引擎直接拦下 |
| 「别改我改过的版本」 | 无从约束 | 读进来是什么版本，写回去就必须还是那个版本，不符即拒 |
| 「别乱跑目录」 | 无从约束 | **只能在项目目录里活动**，越界即拒；记忆目录受保护 |
| 「别把一次结果塞爆上下文」 | 无从约束 | 单次结果过大就截断，**不让它拿半截结果当完整** |
| 「卡住了就停，别空转烧钱」 | 无从约束 | 原地打转就**直接停下**，不空转到超时 |
| 「调工具就规规矩矩地调」 | 模型偶尔把调用写成一段标记文本，整轮就废 | 引擎会把**走形的调用还原成真正的调用**，不让整轮卡死 |
| 「按阶段给该给的信息」 | 靠轮次约定 | 阶段之间传的是**结构化数据**，拼错当场就报错，不会悄悄错 |

**一句话：提示词负责「说清要什么」，引擎负责「确保它真做到」。**

> **一处不吹的分寸**：上面第一条「阶段只给该给的工具」是**广告层**约束 ——
>
> 引擎只是把该有的工具**告诉**模型，并不是每次调用都再验一遍。
>
> 其余几条才是**执行时硬拦**，绕不过去。

最后一句没说的：这也正是它**换到不同模型上都还有底**的原因 —— 守规矩靠边界，不靠运气。

## 记忆：清空上下文之后，它怎么还记得

每轮对话结束都清空上下文，那「上次说了什么」靠什么记住？

答案就是记忆系统 —— 上下文只带这一轮该带的部分，其余全部落进 `.memory/`，按需召回。

**记得多，却不占上下文。**

**四层记忆**（归档 / 观测日志 / 知识图谱 / 业务库），都落在项目本机：

| 层 | 存什么 |
|---|---|
| **归档** | 原始回合：你的消息、它的回答、token 计数 |
| **观测日志** | 从对话里抽出的**事实 / 偏好 / 决策 / 约束 / 教训**，可语义检索 |
| **知识图谱** | 节点 + 边，按 `(kind, name)` 幂等更新 —— 项目的结构化记忆 |
| **业务库** | 自由 schema，放你自己的业务数据 |

检索是**六路混合召回 + RRF 排名融合**：三层各自做本地语义（多语言嵌入，384 维）与关键词召回，
六路各先排名，再按 RRF 融合成一串候选，最后由一轮 LLM 精排去重，一次拿到最相关的十条。

纯本机 SQLite，**不提交、不上传、没有遥测**；每个项目一份，跟着项目走；还能**只读**检索兄弟项目的记忆。

**它不必把整段历史塞进上下文，也能记得住 —— 这正是不爆上下文的底气。**

## 还有这些

- **纯 Rust 单二进制** —— 运行期不需要 Python / Node / JVM。
- **嵌入模型也编进二进制** —— 语义检索用的多语言嵌入模型（约 85 MB，gzip 内嵌；解压后约 113 MB）随程序分发，首次启动自动解压到本地缓存。
  **不调任何外部嵌入 API，也不需要联网下载模型。**
- **多模型可配置** —— 模型是外置配置：OpenAI / Anthropic 两种方言 × 多模型组，改完重启生效，**加来源零改代码**。
- **可自证的元认知平台** —— 不必信广告词，直接问它「把当前的工具白名单列出来」，它去读**引擎运行时的真值**再回答。
- **自动模式** —— `/auto <目标>` 拉起 Main + Auditor 双 agent 闭环：一个执行、一个独立验收，循环纠错到通过；跑在隔离工作树里。
- **MCP 原生** —— 基于官方 `rmcp` SDK，MCP server 接入为工具（仅工作阶段可见）。
- **CC 风格 TUI** —— ratatui 单栏界面，应用内翻页，底部常驻 token / 上下文组成。
- **人机同源帮助** —— AI 侧 `help` 工具与内置帮助读**同一份**文档（19 个主题）。

## 一轮对话里发生了什么

你发一句话，背后走三步 —— 每步的工具与时限都由引擎定：

| 阶段 | 干什么 | 工具 | 超时 |
|---|---|---|---|
| **组织上下文** | 从记忆里挑出这一轮真正该带的信息 | 14 种（**不碰文件与命令**） | 600s |
| **工作阶段** | 流式作答 + 读写文件 / 执行命令 / MCP / 桌面操作 | 39 种 | 不限 |
| **沉淀阶段** | 把这一轮的事实、决策、教训写回记忆 | 15 种 | 600s |

**工作阶段不限时**；组织与沉淀各限 600 秒 —— 它们是准备与收尾，不该拖。

## 自动模式：让两个 agent 互相盯

单轮对话是「三阶段」；**自动模式**则在这个基础上，把「干」和「验」拆成两个 agent，循环推进：

```
   Main（全工具）—— 执行、改代码、交产出
        │
        ▼
   Auditor（只读 + 检索）—— 验收、挑错、给结构化反馈
        │
        ├─ 通过   → 本轮收工；任务全做完则整个会话结束
        └─ 不通过 → 把 feedback 回注 Main，进入下一轮（循环）
```

- **敲 `/auto <目标>` 开始** —— 例如 `/auto 修复 calc.py 的 add 函数，让 test_calc.py 通过`。
  Main 一轮轮做，Auditor 一轮轮验；**没有固定轮数上限**，直到 Auditor 判定通过、任务做完、或你按 `Esc` 停下。
- **两个角色是真正隔离的**：各有**自己的工具白名单、自己的记忆区**（`.memory/main/` / `.memory/auditor/`）。
  Auditor 被剥掉 7 个写工具（改文件、删文件、写记忆……），**物理上只能看、只能判** —— 这就是「独立审计」的硬保证。
- **跑在隔离的 git 工作树里**：每个会话在 `auto-sessions/<sid>` 里动手，每轮 checkpoint，**主工作树不被污染**。
- **过程可见**：左下角与对话活动行常驻显示「第 N 轮 · Auto·Main / Auto·Auditor」，随时能看到它跑到哪了。

只想做一次「产出 → 审计」、不要长跑循环？用 **`/round <目标>`** —— 一次 Main→Auditor（Auditor 不通过就重试，上限 20 次），不建工作树、不落库。

**为什么有效**：纠错的内容会变成执行方下一轮的上下文 —— **让模型自己给自己补上下文**。
单 agent 再强也是无状态的；两个无状态模型经 Harness 协同、互相盯住，就能逼近「接近人的决策」。这也正是灵妙那句主张的延展：**模型不是瓶颈，Harness 才是。**

## 快速开始

**国内能直接用吗？** 能。默认模型组就是 DeepSeek，`base_url` 直连国内接口，不需要代理 —— 密钥只放在本机 `.env`。

**在什么系统上跑？** 目前只提供 **Linux x86_64** 二进制，推荐 **Ubuntu 24.04 LTS**（见[系统要求](#系统要求)）。

**本仓库开源；不提供任何 API key。** 预编译二进制随仓库一起提供，克隆后跑一条命令即可拿到程序。

模型 key 由你用仓库自带的两个模板（`config.example.json` / `.env.example`）自行配置，三分钟跑起来 —— 见[安装部署](#安装部署)。

**数据都在本机**：记忆落 `.memory/`（纯本机 SQLite，不提交、不上传）；嵌入模型随二进制分发，**不调任何外部嵌入 API，也不需要联网拉模型**。

网络只用于你配置的模型 endpoint。

```sh
# 取回预编译二进制 —— 一条命令下载、校验、解压
git clone https://github.com/bmoonx/lingmiao-agent.git
cd lingmiao-agent && ./install.sh        # 无需 Python / Node / Rust
```

> 也可以不克隆仓库，直接跑安装器（只取二进制）：
>
> `curl -fsSL https://raw.githubusercontent.com/bmoonx/lingmiao-agent/main/install.sh | bash`

装好后，在项目目录里敲一句 `lingmiao`，等几秒加载完就进入 TUI —— **当前目录就是它的工作路径**。
完整用法见[使用方法](#使用方法)。

> 灵妙是本地运行的引擎，不提供模型服务、不收集用户数据；模型 key 由使用者自行配置。
>
> 请遵守所用模型服务商的服务条款与所在地法律法规。

## 安装部署

### 系统要求

**只提供 Linux x86_64 的预编译二进制，推荐 Ubuntu 24.04 LTS。**

**Windows 用户建议通过 WSL2 运行 Ubuntu 24.04 来使用。**

| 项 | 要求 |
|---|---|
| 操作系统 | **Ubuntu 24.04 LTS**（推荐） |
| CPU 架构 | x86_64（amd64） |
| 运行环境 | 需真实终端（stdout 是 tty） |

二进制动态链接系统的 glibc / libstdc++，**要求 glibc ≥ 2.39**。

Ubuntu 24.04 LTS 自带 glibc 2.39，正好满足 —— **目前只有这一个系统实测跑通**。

更旧的发行版（如 Ubuntu 22.04 的 glibc 2.35、Debian 12 的 glibc 2.36）**跑不起来**，启动会报 `GLIBC_2.39 not found`。

> 目前**只发布 Linux x86_64 一个平台** —— 没有 macOS 版，也没有 ARM 版。

### 安装预编译二进制（一条命令）

可执行文件（含内嵌嵌入模型）约 140 MB，超过 GitHub **仓库**单文件 100 MB 的上限，所以它作为 **Release 资产**发布；仓库里配一个安装器 `install.sh` 负责「下载 → 校验 → 解压 → 就位」。

```sh
git clone https://github.com/bmoonx/lingmiao-agent.git
cd lingmiao-agent && ./install.sh        # 产出 ./dist/lingmiao-<版本>-<平台>/lingmiao
./dist/lingmiao-<版本>-<平台>/lingmiao
```

安装器会校验 SHA-256，**下载不全或文件损坏都会报错，不会给你半个程序**。

只依赖系统的 `bash` / `curl` / `tar` / `sha256sum`，**不用装 Rust / Python / Node**。

不想克隆仓库、只想要二进制？直接跑安装器：

```sh
curl -fsSL https://raw.githubusercontent.com/bmoonx/lingmiao-agent/main/install.sh | bash
```

也可以在 [Releases](https://github.com/bmoonx/lingmiao-agent/releases) 页面手动下载 `lingmiao-<版本>-linux-x86_64.tar.gz` 解压。

首次运行会在**当前目录**创建 `.memory/`（持久记忆）与 `.cache/lingmiao/`（易失：日志 / 临时 / loop 状态）。

启动时还会把内嵌的嵌入模型解压到 `~/.cache/lingmiao-models/`（约 113 MB，只需一次；之后离线也能用）。

交互式 TUI **需要真实终端**（stdout 是 tty）；否则程序打印一行摘要后退出。

> 源代码随仓库一起提供（`cargo build --release` 可自行从源码构建）；Release 只提供 **Linux x86_64** 预编译二进制，macOS / ARM 等其它平台暂未提供。

> 本仓库**不提供任何 API key** —— key 由你自行申请并配置（下一节）。

### 装好之后：配置你自己的模型

灵妙**不带 key**，启动前需要配好「模型来源 + 密钥」。仓库里随附两个模板，复制改一改即可：

| 模板 | 复制为 | 作用 |
|---|---|---|
| [`.env.example`](.env.example) | `.env` | 放 **API key**（最省事，用内置来源时只改这一个） |
| [`config.example.json`](config.example.json) | `config.json` | **模型目录 + 阶段路由**（加自己的来源、或让某阶段用别的模型时才需要） |

**第一步：写 key。** 只填你要用的组——默认组是 DeepSeek，填它就够启动：

```sh
mkdir -p ~/.lingmiao && cp .env.example ~/.lingmiao/.env
# 编辑 ~/.lingmiao/.env，填上你的 key：
#   DEEPSEEK_API_KEY=sk-xxxxxxxx   # 申请：platform.deepseek.com
#   KIMI_API_KEY=sk-xxxxxxxx       # 可选
```

> 也可以把 `.env` 放在**二进制同级**或**当前目录**（程序会按 `~/.lingmiao/.env` → `$LINGMIAO_HOME/.env` → 二进制同级 → 当前目录上溯 ≤5 级 的顺序查找）。`.env` 已进 `.gitignore`，不会被提交。

**第二步（可选）：加自己的模型来源。**

想用智谱 GLM / 通义 / 任何 OpenAI 兼容端点，把 `config.example.json` 复制成 `config.json`（放**二进制同级**或**当前目录**），在 `models.groups` 里加一个 group —— **零改代码**：

```jsonc
{
  "models": {
    "groups": [
      {
        "id": "zhipu",
        "label": "智谱 GLM",
        "protocol": "openai",                              // 绝大多数来源都是 openai 方言
        "base_url": "https://open.bigmodel.cn/api/paas/v4",
        "api_key_env": "ZHIPU_API_KEY",                    // 指向 .env 里的变量名，不写明文
        "models": [{ "id": "glm-4.6", "label": "GLM-4.6" }]
      }
    ]
  }
}
```

`config.json` 还有 `stages` 段，可以把**每个阶段指到不同的 group/model**（例如对话用 DeepSeek、沉淀阶段用 Kimi）。

一个 group 就是一个 API 来源 —— 一条 `stages` 条目，就能让某阶段走另一家厂商。

> 模板见仓库根目录 [`config.example.json`](config.example.json)（已带 DeepSeek / Kimi / Claude / 智谱 四个样例组）。
>
> 两个文件都**改完重启生效**；复制过去后请**按需删掉**用不到的样例组与 key 变量。
>
> 应用内 `/help` 或直接问 AI 可查全部 19 个帮助主题。

> **不想配？** 内置 DeepSeek 组是默认，只要 `DEEPSEEK_API_KEY` 有值就能启动；
>
> 连 `config.json` 都不需要（`models.json` 也仍兼容）。

装好之后怎么用（敲什么、等多久、当前目录就是工作路径）见下一节[使用方法](#使用方法)。

## 使用方法

装好、配好 key 之后，使用就两步：

```sh
cd 你的项目          # 当前路径 = 工作路径
lingmiao             # 直接敲，没有参数
```

> `lingmiao` 指你装好的那个可执行文件 —— 想全局敲它，就把 `install.sh` 产出的二进制放进 `PATH`（或软链一下：`ln -sf "$PWD/lingmiao" /usr/local/bin/lingmiao`）；不然直接用它的路径调也可。

1. **等几秒。** 敲下 `lingmiao` 后先加载系统（初始化记忆库、把内嵌模型解压到本地缓存）；缓存已就绪就是秒级，几秒后进入 TUI。

   **首次启动会慢一些**：要解压内嵌模型、重建一次向量索引，可能要**几分钟**。

   之后就都是几秒的事 —— 除非你换过嵌入模型、或删掉过模型缓存。
2. **操作和 Claude Code 一样。** 一句话回车，它就流式作答；边跑边看、随时上翻、`/` 开斜杠命令、
   `⌃C` 连按两次退出。键位见下。
3. **没有参数。** 一句 `lingmiao` 就是全部 —— 没有子命令、也没有启动开关，进 TUI 之后全在里面操作。

### 当前路径，就是它的工作路径

**你在哪个目录敲 `lingmiao`，它就把哪个目录当作项目根** —— 读写的文件、执行的命令都在这里。

`.memory/`（持久记忆）与 `.cache/lingmiao/`（日志 / 临时）也直接建在当前目录下。

**所以记忆是「跟着项目走」的**：换个目录启动，就是换一份全新的记忆；
把项目目录连同 `.memory/` 一起拷走，它到新机器上还是原来那个它。

### 几个常用操作

| 操作 | 作用 |
|---|---|
| 输入一句话 + 回车 | 提交一轮：**组织上下文 → 工作阶段 → 沉淀阶段** |
| `/` | 斜杠命令面板：`/help` `/memory` `/tools` `/model` `/auto` `/round` `/clear` `/quit` 等 |
| `/auto <目标>` | **自动模式**：Main 执行 + Auditor 独立验收，循环到通过（`Esc` 停止） |
| `/round <目标>` | **单轮审计**：一次「产出 → 审计」，不建工作树、不落库 |
| `PageUp` / `PageDown` | 上下翻对话（`⌃Home` / `⌃End` 直接到顶 / 到底） |
| `⌃O` | 展开 / 收起被折叠的推理与工具输出 |
| `Esc` | 打断正在进行的回答 |
| `⌃C` 连按两次 | 退出（第一次给提示；有拖选时 `⌃C` 只复制） |
